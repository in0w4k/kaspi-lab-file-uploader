# KaspiLAB Final Project (file-uploader)

## 🚀 Обзор проекта

Проект представляет собой высокопроизводительный, асинхронный сервис для загрузки файлов, реализованный на базе **Spring WebFlux**. Ключевой акцент сделан на неблокирующем вводе/выводе (non-blocking I/O), обеспечении **идемпотентности** по содержимому файла (content-based idempotency) и гарантированной консистентности данных между файловым хранилищем и базой метаданных.

## 🎯 Требования (ТЗ Проект 1)

| Требование                | Статус | Детали реализации                                                                                                                           |
|:--------------------------|:-------|:--------------------------------------------------------------------------------------------------------------------------------------------|
| **Прием файла**           | ✅      | REST Endpoint (`POST /api/files`) принимает `multipart/form-data`.                                                                          |
| **Асинхронная обработка** | ✅      | Использование **Spring WebFlux** и **S3AsyncClient** гарантирует, что HTTP-поток не блокируется.                                            |
| **Идемпотентность**       | ✅      | Файл сохраняется на диск, вычисляется **SHA-256 хеш** его содержимого. Повторный запрос с тем же контентом не приводит к дублированию.      |
| **Неблокирующий I/O**     | ✅      | Операции с диском (сохранение temp-файла, хеширование) выполняются в выделенном пуле `Schedulers.boundedElastic()`, не блокируя Event Loop. |
| **Консистентность**       | ✅      | Логика: 1. Загрузка в S3. 2. Запись метаданных в Mongo. При ошибке на любом из шагов выполняется **Cleanup** (удаление файла из S3).        |
| **Освобождение ресурсов** | ✅      | Временные файлы на диске гарантированно удаляются через `doFinally`, независимо от успеха операции.                                         |

## 🛠️ Технологический стек

*   **Backend:** Java 21, Spring Boot 3.x
*   **Реактивность:** Spring WebFlux, Project Reactor
*   **База данных:** MongoDB (ReactiveMongoRepository)
*   **Файловое хранилище:** MinIO (эмулирует AWS S3)
*   **S3 Клиент:** AWS SDK v2 (Async Client)
*   **Контейнеризация:** Docker, Docker Compose

## 📦 Запуск проекта

### 1. Предварительные требования

Убедитесь, что у вас установлены **Docker** и **Docker Compose**.

### 2. Сборка и запуск

Сервис использует **MongoDB** для метаданных и **MinIO** для хранения файлов.

```bash
docker compose build
docker compose up -d
```

### ⚠️ Важно: Создание S3 бакета

Поскольку автоматическое создание бакета в MinIO может быть нестабильно при первом запуске, выполните эту команду вручную, чтобы убедиться, что бакет **`uploads`** создан:

```bash
docker run --net=host minio/mc alias set myminio http://localhost:9000 admin password
docker run --net=host minio/mc mb myminio/uploads
```

Либо через интерфейс **Docker Desktop** нужно запустить `createbuckets-1` в контейнере `final-project-1`.

Проект будет доступен по адресу `http://localhost:8080`.

## 🚀 Использование API

### Загрузка файла

Для загрузки файла используется `POST` запрос в формате `multipart/form-data`.

**Endpoint:** `POST /api/files`
**Content-Type:** `multipart/form-data`
**Response:** `202 Accepted`

**Пример (cURL):**

```bash
curl -X POST http://localhost:8080/api/files \
     -H 'Content-Type: multipart/form-data' \
     -F 'file=@/path/to/your/document.pdf'
```

#### Ответ при успешной загрузке (HTTP 202 Accepted)
